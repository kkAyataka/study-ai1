# 仕様と設計判断

ToDoアプリのバージョン1（MVP）の仕様と、その仕様にした理由をまとめます。次のバージョンで何かを変えるときは、まずこの文書の前提が今も正しいかを確認してください。

## 前提

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 目的 | 自分が毎日使う実用ツール | 学習用の題材ではなく、実際に使い続けるもの |
| 利用者 | 自分ひとり。ログインなし | 複数人にすると認証やサーバー側のデータベースが必要になり、作業量が数倍になる |
| 動かす場所 | Webブラウザ | |
| 使う端末 | 1台のPCのブラウザだけ。端末間の同期なし | 同期にはサーバーかクラウドストレージが必要。必要を感じてから追加する |
| 見た目 | 最低限のCSS | まず使い始めて、使いながら直す |
| 画面の言葉 | 日本語 | |

## 機能（バージョン1）

### タスクの追加

- 入力の前後の空白は自動で取り除く。
- 空白だけの入力では追加しない。
- 文字数の上限は設けない。
- 追加したら入力欄を空にする。

### 一覧表示

- 新しいタスクを一番上に表示する。
- 完了したタスクは、取り消し線を付けてその場に残す（下にまとめたり非表示にしたりはしない）。
- タスクが1件もないときは「タスクはありません」と表示する。

### 完了チェック

- チェックボックスで完了と未完了を切り替える。

### 削除

- 削除の前に確認ダイアログ（`「〇〇」を削除しますか？`）を出す。
- 削除の取り消し機能は、実装が重いので見送った（後回しにした機能の一覧を参照）。

### 書き出し（バックアップ）

- ファイル名は `todos-YYYY-MM-DD.json`。日付は書き出した日で、ローカル時刻（日本時間）を使う。
- 中身は、localStorage に保存しているデータそのもの（下の「データ形式」を参照）。

### 読み込み（復元）

- 今のタスクを全部置き換える（追加はしない）。バックアップから復元する用途に合わせた。
- 置き換える前に「今のタスクは全部消えます」と確認を出す。
- 次のチェックをしてから読み込む。1つでも引っかかったら、エラーを表示して今のタスクには手を付けない。
  - JSONとして読めるか
  - データのバージョン番号が対応しているものか
  - 各タスクの項目の型が正しいか
- 読み込んだタスクは、作成日時の新しい順に並べ直す。手で編集したファイルでも表示順が崩れないようにするため。

### 画面の配置

上から順に「入力欄と追加ボタン」「タスク一覧」「書き出し・読み込みボタン」。書き出し・読み込みはたまにしか使わないので、一番下に置く。

## データ

### 保存先

ブラウザの localStorage（キー: `study-ai1.todos`）。

- IndexedDB も検討したが、ToDo程度のデータ量なら localStorage で十分で、実装もシンプル。
- 保存処理は `src/storage.ts` にまとめてある。将来、同期などで保存先を変えるときは、ここを差し替える。
- ブラウザのデータを消すとタスクも消える。この対策として、書き出し・読み込み機能を最初のバージョンに入れた。
- localStorage は URL（オリジン）ごとに分かれている。そのため開発用サーバーと公開URLのデータは混ざらない。

### データ形式

```json
{
  "version": 1,
  "todos": [
    { "id": "…", "title": "牛乳を買う", "completed": false, "createdAt": "2026-11-21T10:00:00.000Z" }
  ]
}
```

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `id` | string | `crypto.randomUUID()` で作る |
| `title` | string | 前後の空白を取り除いた文字列 |
| `completed` | boolean | 完了したかどうか |
| `createdAt` | string | ISO 8601 形式の作成日時。並び順に使う |

- データの形を変えるときは `version` を上げる。期限や優先度を足すときなどが該当する。そのうえで、古いバージョンを読めるように変換処理を書く。
- 今は、対応していないバージョンや壊れたデータを読むと、空の一覧として扱う。変換処理を書くときに、この動きも見直す。

## テスト方針

TDD（先にテストを書いてから実装する）で進める。テストは次の3か所に書く。

| テストする場所 | 確かめること | 確かめないこと |
| --- | --- | --- |
| 画面全体（`App`） | 利用者と同じ操作で、追加・空白の扱い・並び順・完了の切り替え・確認付きの削除・0件のときの表示・開き直したときにタスクが残っていること | 見た目やCSS |
| `storage` | 保存したものをそのまま読み戻せること、壊れたデータや未対応バージョンのデータを安全に扱うこと | 画面との連携 |
| `backup` | 書き出したものをそのまま読み込めること、ファイル名、不正なファイルをエラーにすること | 実際のファイル選択とダウンロード（ブラウザで手動確認） |

タスクの追加・完了・削除のロジックは、専用のテストを書かずに画面テストでまとめて確かめる。内部の構造を変えても、テストを書き直さずに済むようにするため。

## 公開

- GitHub Pages で公開する。毎回開発サーバーを起動しなくても、URLを開くだけで使えるようにするため。
- 無料プランの GitHub Pages は公開リポジトリでしか使えないので、リポジトリは public にした。公開されるのはコードだけで、タスクのデータは各自のブラウザ内にある。
- `main` にプッシュすると、GitHub Actions が lint・テスト・ビルドを実行し、すべて通った場合だけ公開する。テストが失敗したら公開されないので、壊れた状態のアプリが届くことを防げる。
- Vite の `base` は `/study-ai1/`。

## 後回しにした機能

次のバージョンの候補:

- タスク名の編集
- 「未完了だけ表示」の絞り込み
- 削除の取り消し（数秒間「元に戻す」ボタンを出す）

その後の候補:

- 期限、優先度、タグ・カテゴリ、サブタスク
- 並び替え
- リマインダー・通知
- 端末間の同期
- ダークモード、スマホ表示への対応
