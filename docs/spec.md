# 仕様と設計判断

ToDoアプリのバージョン1（MVP）と、そのあとに足した機能の仕様、その仕様にした理由をまとめます。用語は [GLOSSARY.md](../GLOSSARY.md) に合わせます。

この文書では、アプリの版を「アプリのバージョン」、保存データの `version` を「データ形式のバージョン」と書き分けます。両者の番号は連動しません（アプリのバージョン1のあとに期限日を足したとき、データ形式はバージョン2になった）。

アプリの次のバージョンで何かを変えるときは、まずこの文書の前提が今も正しいかを確認してください。

## 前提

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 目的 | 自分が毎日使う実用ツール | 学習用の題材ではなく、実際に使い続けるもの |
| 利用者 | 自分ひとり。ログインなし | 複数人にすると認証やサーバー側のデータベースが必要になり、作業量が数倍になる |
| 動かす場所 | Webブラウザ | |
| 使う端末 | 1台のPCのブラウザだけ。端末間の同期なし | 同期にはサーバーかクラウドストレージが必要。必要を感じてから追加する |
| 見た目 | 最低限のCSS | まず使い始めて、使いながら直す |
| 画面の言葉 | 日本語 | |

## 機能（アプリのバージョン1）

### タスクの追加

- 入力の前後の空白は自動で取り除く。
- 空白だけの入力では追加しない。
- 文字数の上限は設けない。
- 追加したら入力欄を空にする。

### 一覧表示

- 並び順が作成順のときは、新しいタスクを一番上に表示する（ほかの並び順は「並び替え」を参照）。
- 完了したタスクは、取り消し線を付けてその場に残す（下にまとめない）。一覧から隠れるのは、未完了だけ表示をオンにしたときだけ（「未完了だけ表示」を参照）。
- タスクが1件もないときは「タスクはありません」と表示する。

### 完了チェック

- チェックボックスで完了と未完了を切り替える。

### 削除

- 削除の前に確認ダイアログ（`「〇〇」を削除しますか？`）を出す。
- 削除の取り消し機能は、実装が重いので見送った（後回しにした機能の一覧を参照）。

### 書き出し

バックアップを取るための機能。

- ファイル名は `todos-YYYY-MM-DD.json`。日付は書き出した日で、ローカル時刻（日本時間）を使う。
- 中身は、localStorage に保存しているデータそのもの（下の「データ形式」を参照）。

### 読み込み

書き出したファイルからタスクを戻すための機能。

- 今のタスクを全部置き換える（追加はしない）。バックアップから復元する用途に合わせた。
- 次のチェックをしてから読み込む。1つでも引っかかったら、エラーを表示して今のタスクには手を付けない（確認も出さない）。
  - JSONとして読めるか
  - データ形式のバージョンが対応しているものか
  - 各タスクの項目の型が正しいか（「データ形式」を参照）
  - `createdAt` が書き出しと同じ形式（`toISOString()` の UTC、ミリ秒付き）の実在する日時か。時差付きなど形式の違う日時が混ざると、文字列の比較で並べ直したときに順番が崩れるため
  - `title` が空や空白だけになっていないか。追加のときと同じ規則にそろえた
  - `id` が重複していないか。重複すると、1件への完了の切り替えが別のタスクにもかかってしまうため
- チェックを通ったら、置き換える前に `今のタスクは全部消えて、ファイルの内容に置き換わります。読み込みますか？` と確認を出す。キャンセルすれば今のタスクのまま。
- 正しいファイルを読み込み直すと、前のエラー表示は消える。
- 読み込んだタスクは、作成日時の新しい順に並べ直す。手で編集したファイルでも表示順が崩れないようにするため。

### 期限日

アプリのバージョン1のあとに追加した。

- 期限日は日付だけで、時刻は持たない。時刻を持たせるとタイムゾーンや「何時を過ぎたら期限切れか」まで決める必要が出るため。時刻はリマインダー・通知を作るときに改めて考える。
- 期限日は任意。付けないタスクも多いため。
- 追加フォームの日付入力欄で、追加するときに指定できる。初期値は空（期限日なし）で、追加したあとは空に戻す。
- 一覧の各行に日付入力欄を置き、表示・変更・解除（空にする）をまとめて行う。作る量が一番少なく、カレンダーでの選択もブラウザがやってくれるため。表示はブラウザの書式になり、曜日は出ない。
- 0001〜9999年でない日付は受け付けず、日付入力欄は元の値に戻る。ブラウザの日付入力欄は5桁以上の年も入力できるが、保存データの形式（`YYYY-MM-DD`）に合わず、保存すると開き直したときに一覧全体が読み込めなくなるため。0000年は形式には合うが、日付入力欄に表示できず空欄に見えてしまうので、読み込むファイルや保存データにあっても正しくない期限日として扱う。
- 今日より前の日付も指定できる。禁止しても日付が変われば期限切れのタスクはできるので、禁止する意味が小さい。
- 並び順は期限日を付けても変わらない。期限日の早い順に見たいときは、並び順で「期限日順」を選ぶ（下の「並び替え」を参照）。

### 期限切れ

- 期限日の翌日になっても未完了のタスクは、タイトルを赤字にする。期限日の当日はまだ期限切れではなく、当日だけの強調もしない。
- 完了したタスクは、期限日を過ぎていても強調しない。期限日は表示したまま。
- 画面を描き直すたびに今日の日付（ローカル時刻）と比べて決める。アプリを開いたまま日付をまたいだ場合は、次に操作するか開き直したときに反映される。日付の変わり目を見張るタイマーは入れていない。

### 並び替え

期限日のあとに追加した。

- 一覧の上に「並び順」のプルダウンを置き、「作成順」と「期限日順」を選べる。初めは作成順。プルダウンにしたのは、場所を取らず、並び順を増やすときもそのまま使えるため。
- 期限日順では、期限日の早いタスクほど上に来る。急ぐものから手を付けられるようにするため。
- 期限日のないタスクは、期限日のあるタスクの後ろにまとめる。
- 期限日が同じタスク同士や、期限日のないタスク同士は作成順に並べる。並びが毎回同じになり、見失わないようにするため。
- 完了したタスクも、下にまとめずに期限日どおりの位置に取り消し線付きで残す。一覧表示の「その場に残す」と同じ考え方にした。
- 期限日を変えたりタスクを追加したりすると、すぐに正しい位置へ移る。
- 並び順は見せ方だけを変える。保存しているタスクの順番（作成順）と書き出しの内容は変わらない。
- 並び順は保存せず、開き直すと作成順に戻る。毎回選び直すのが面倒になったら保存を足す。

### 未完了だけ表示

並び替えのあとに追加した。

- 「並び順」の横に「未完了だけ表示」のチェックボックスを置く。オンにすると完了したタスクを一覧から隠し、オフにすると戻す。初めはオフ。
- 並び順とは別に操作でき、組み合わせて使える（期限日順で未完了だけ、など）。
- 絞り込み中に追加したタスクは一覧に表示される（追加したばかりのタスクは未完了のため）。
- 絞り込み中に完了にしたタスクは、すぐに一覧から消える。間違えて完了にしたときは、絞り込みを外せば見つけて戻せる。消えるまで少し待つ仕組みは入れていない。
- 隠れたタスクは消えたわけではない。完了の切り替え・期限日の変更・削除は、表示されているタスクに対して今までどおりできる。
- 未完了のタスクが1件もないときは「未完了のタスクはありません」と表示する。タスクが1件もないときは、絞り込み中でも「タスクはありません」と表示する。全部消えたように見えて驚かないようにするため。
- 絞り込みは見せ方だけを変える。保存しているタスクと書き出しの内容には、隠れているタスクも含めてすべて入る。バックアップからタスクが抜けないようにするため。
- 絞り込みは保存せず、開き直すとオフに戻る。

### 画面の配置

上から順に「入力欄（タスク名・期限日）と追加ボタン」「並び順と未完了だけ表示」「タスク一覧」「書き出し・読み込みボタン」。書き出し・読み込みはたまにしか使わないので、一番下に置く。

## データ

### 保存先

ブラウザの localStorage（キー: `study-ai1.todos`）。

- IndexedDB も検討したが、ToDo程度のデータ量なら localStorage で十分で、実装もシンプル。
- 保存処理は `src/storage.ts` にまとめてある。将来、同期などで保存先を変えるときは、ここを差し替える。
- ブラウザのデータを消すとタスクも消える。この対策として、書き出し・読み込み機能をアプリの最初のバージョンに入れた。
- localStorage は URL（オリジン）ごとに分かれている。そのため開発用サーバーと公開URLのデータは混ざらない。

### データ形式

```json
{
  "version": 2,
  "todos": [
    { "id": "…", "title": "牛乳を買う", "completed": false, "createdAt": "2026-11-21T10:00:00.000Z", "dueDate": "2026-11-25" }
  ]
}
```

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `id` | string | `crypto.randomUUID()` で作る |
| `title` | string | 前後の空白を取り除いた文字列 |
| `completed` | boolean | 完了したかどうか |
| `createdAt` | string | 作成日時。`toISOString()` の形式（UTC、ミリ秒付き。例: `2026-11-21T10:00:00.000Z`）。並び順に使う |
| `dueDate` | string または null | 期限日（`YYYY-MM-DD`）。期限日なしなら `null`。省略はできない |

- データの形を変えるときはデータ形式のバージョン（`version`）を上げ、古いバージョンを読めるように変換処理を書く。
- データ形式のバージョン2で `dueDate` を足した。バージョン1のデータ（localStorage とバックアップファイルの両方）は、期限日なし（`null`）のタスクとして読み込む。保存と書き出しは常にバージョン2。
- `dueDate` は年月日だけの文字列にした。タイムゾーンで日付がずれず、手で直すときも読みやすいため。
- 読み込むファイルに実在しない日付（`2026-02-30` など）や時刻付きの値が1つでもあれば、ほかの型の誤りと同じくファイル全体をエラーにする。
- 対応していないデータ形式のバージョン（1と2以外。`version` がない場合も含む）や壊れたデータを localStorage から読むと、空の一覧として扱う。
- 読み込みでだけ行うチェック（`createdAt` の形式、空の `title`、`id` の重複）は、localStorage から読むときには行わない。アプリ自身が書いたデータで、読み込みで弾いた値は入らないため。ここで弾くと、空の一覧として扱ったあとの保存でタスクが全部消えてしまう。
- **アプリの新しいバージョンを公開したら、開いたままの古いタブは開き直すこと。** 古いバージョンのアプリで操作すると、期限日のないデータ形式のバージョン1で上書きされ、期限日が消える。利用者がひとりで、開き直すだけで防げるので、仕組みでは防いでいない。

## テスト方針

TDD（先にテストを書いてから実装する）で進める。テストは次の3か所に書く。

| テストする場所 | 確かめること | 確かめないこと |
| --- | --- | --- |
| 画面全体（`App`） | 利用者と同じ操作で、各機能が仕様どおりに動くこと（下の一覧） | 見た目やCSS |
| `storage` | 保存したものをそのまま読み戻せること、データ形式のバージョン1を読めること、壊れたデータ（正しくない期限日を含む）や未対応バージョンのデータを安全に扱うこと、読み込みでだけ行うチェックをかけないこと | 画面との連携 |
| `backup` | 書き出したものをそのまま読み込めること、データ形式のバージョン1のファイルを読めること、ファイル名、不正なファイル（正しくない期限日・`createdAt`、空の `title`、`id` の重複を含む）をエラーにすること | 実際のファイル選択とダウンロード（ブラウザで手動確認） |

画面全体のテストで確かめること:

- タスク：追加、空白の扱い、作成順での並び、完了の切り替え、確認付きの削除、0件のときの表示、開き直したときにタスクが残っていること
- 期限日：指定・変更・解除、保存できない期限日を受け付けないこと、期限切れの赤字
- 期限日順：期限日なしは一番下、同じ期限日は作成順、完了したタスクもその位置に残ること、完了・期限日の変更と解除・追加のあとも正しく並ぶこと、作成順に戻せること、期限切れの赤字が残ること、書き出しと保存は作成順のままで開き直すと作成順に戻ること
- 未完了だけ表示：完了したタスクを隠すこと、絞り込み中に完了にするとすぐ消えること、絞り込み中も追加・期限日の変更・削除ができること、0件のときの2種類の文言、期限日順との組み合わせ、書き出しにはすべてのタスクが入り開き直すとオフに戻ること
- 読み込み：確認してから全部置き換えて作成日時の新しい順に並べること、キャンセルすると今のタスクのままなこと、不正なファイルではエラーを出して確認も出さず今のタスクに手を付けないこと、正しいファイルを読み込み直すとエラーが消えること

タスクの追加・完了・削除のロジックは、専用のテストを書かずに画面テストでまとめて確かめる。内部の構造を変えても、テストを書き直さずに済むようにするため。

## 公開

- GitHub Pages で公開する。毎回開発サーバーを起動しなくても、URLを開くだけで使えるようにするため。
- 無料プランの GitHub Pages は公開リポジトリでしか使えないので、リポジトリは public にした。公開されるのはコードだけで、タスクのデータは各自のブラウザ内にある。
- `main` にプッシュすると、GitHub Actions が lint・テスト・ビルドを実行し、すべて通った場合だけ公開する。テストが失敗したら公開されないので、壊れた状態のアプリが届くことを防げる。
- Vite の `base` は `/study-ai1/`。

## 後回しにした機能

アプリの次のバージョンの候補:

- タスク名の編集
- 削除の取り消し（数秒間「元に戻す」ボタンを出す）

その後の候補:

- 優先度、タグ・カテゴリ、サブタスク
- リマインダー・通知
- 端末間の同期
- ダークモード、スマホ表示への対応
