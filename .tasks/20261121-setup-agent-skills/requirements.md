# 要件のやり取り

スキルの手順では1項目ずつ質問することになっているが、3つの質問はどれも互いに独立していたので、1回の質問でまとめて聞いた。各質問には Claude の推奨案を付けた。

## ラウンド1

| # | 質問 | 推奨 | 回答 |
| --- | --- | --- | --- |
| Q1 | 課題（issue）をどこで管理するか。origin が GitHub の `kkAyataka/study-ai1` で、Issues は有効 | GitHub Issues（`gh` CLI） | Yes |
| Q2 | triage ラベルを標準の名前（`needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`）のままにするか | 標準のまま | Yes |
| Q3 | `CLAUDE.md` も `AGENTS.md` もないので、どちらを作るか | （推奨なし。スキルの決まりで、ユーザーに選んでもらう） | `CLAUDE.md` |

## 推奨と違う回答になった点

なし。

## Claude が独断で決めた点

- **用語集の構成**：monorepo の兆候（`pnpm-workspace.yaml`、`workspaces`、`packages/`）がなかったので、スキルの決まりどおり単一コンテキストにし、質問しなかった。
- **下書きの確認を省いた**：スキルでは書き込む前に下書きを見せることになっている。今回はすべて推奨どおりでテンプレートをほぼそのまま使うため、下書きは見せずに書き込んだ。
- **PR を依頼として扱う設定**：テンプレートの初期値（off）のままにし、話題にも出さなかった（スキルの指示どおり）。
- **ラベルの色と説明**：`gh label create` で付ける色は Claude が選び、説明はテンプレートの表の文言を英語のまま使った。
- **コミット先**：ユーザーの依頼を受けて、ブランチを作らずに `main` へ直接コミットした。これまでのコミットも `main` に直接入っていたため。
