## 3. #2 期限日順の並び替え（/tdd）

1. 「初めは作成順で、期限日順を選ぶと期限日の早い順に並ぶ」：失敗を確かめてから、`src/todo.ts` に `SortOrder` 型と `sortTodos` を、`src/App.tsx` に「並び順」のプルダウンを足した。

3. 「完了・期限日の変更・追加のあとも正しく並び、作成順に戻せる」：表示のたびに並べ替えているので、最初から通った。完了したタスクを下にまとめる誤った実装を一時的に入れ、失敗することを確かめた。

## 7. 振り返り（/retro）

環境の改善候補を5つ挙げた。ユーザーの判断で、今回はどれも実施していない。

1. `gh` がサンドボックスの中で TLS の検証に失敗する。`sandbox.excludedCommands` に `'gh *'` を足せば直る（フォークしたセッションで公式ドキュメントを読んで確認済み）
2. コミットの前に lint・テスト・ビルドを自動で走らせる仕組みがない（`check` スクリプトと pre-commit の案）
3. レビューで使う規約が1か所にまとまっていない（`CODING_STANDARDS.md` の案）
4. README のディレクトリ構成の表が、機能を足すたびに古くなる
5. 公開の GitHub Actions の状態がエージェントから見えにくい

## つまずいた点

- **`gh` がサンドボックスで動かない**: 最初は通信先の許可がないというエラー、次は TLS の証明書の検証エラー（`x509: OSStatus -26276`）になった。issue の操作と push は、毎回サンドボックスを外して実行した。レビュー用のサブエージェントも同じエラーにぶつかった。
- **最初から通るテスト**: 並び替えと絞り込みを表示のたびに計算するので、いくつかのテストは実装前から通った。そのたびに誤った実装を一時的に入れて、テストが間違いを見つけられることを確かめた。
- **テスト環境にない `URL.createObjectURL`**: 書き出しのテストでは、jsdom にないこの関数を差し替える必要があった。最初の実装では差し替えたまま元に戻していなかった。#3 のレビュー後に `exportTitles` で、押したあとに元に戻すようにした。
- **公開の待ち**: 最後の push の直後、GitHub Actions は `waiting` の状態だった。記録を書くときに確かめると、3回の公開はすべて成功していた。
