# 要件の質問と回答

依頼は「`/grill-with-docs` 期日順の並び替えと、未完了だけを表示するフィルタを追加したい」。grilling スキルと domain-modeling スキルで、決めることを前提が決まったものから順にラウンドごとに質問した。各質問には Claude の推奨案を付け、ユーザーが答えた。

質問の前に [GLOSSARY.md](../../GLOSSARY.md)、[docs/spec.md](../../docs/spec.md)、`src/todo.ts`、`src/App.tsx` を読み、次のことを確認した。

- 一覧は作成日時の新しい順で固定
- 仕様書では「並び替え」と「未完了だけ表示の絞り込み」は、どちらも後回しにした機能
- 用語集では「期日」は避ける言葉で、正しくは「期限日」

## ラウンド1：並び替えと絞り込みの振る舞い

| # | 質問 | 推奨 | 回答 |
| --- | --- | --- | --- |
| Q1 | 用語 | 「期日」ではなく「期限日順」。今の並び順は「作成順」。どちらも用語集に追加 | Yes |
| Q2 | 並び替えの方式 | 作成順／期限日順を切り替える。初期値は作成順 | Yes |
| Q3 | 期限日のないタスク | 期限日順の一番下にまとめる | Yes |
| Q4 | 期限日が同じタスク | 作成順で並べる | Yes |
| Q5 | 完了したタスク | 期限日順でも、下にまとめずその場に残す | Yes |
| Q6 | 絞り込みと並び替えの関係 | 別々に操作でき、組み合わせられる | Yes |
| Q7 | 絞り込み中に完了にしたとき | すぐに一覧から消える | Yes |
| Q8 | 絞り込みで0件のとき | 「未完了のタスクはありません」と出し、「タスクはありません」と分ける | Yes |
| Q9 | 設定の保存 | 保存せず、開き直すと「作成順・すべて表示」に戻る | Yes |
| Q10 | 操作の置き場所 | 追加フォームと一覧のあいだ | Yes |

このあと GLOSSARY.md に **作成順**・**期限日順**・**未完了だけ表示** を登録した。

## ADR について

どの決定もあとから簡単に変えられるので、ADR は作らなかった。

## Claude が独断で決めた点

- issue のタイトルと受け入れ条件は、依頼の「期日順」「フィルタ」ではなく、用語集の言葉（期限日順・未完了だけ表示）で書いた。
- #3 を #2 の後にした理由（組み合わせの受け入れ条件と、同じ画面の部分を触ること）は、Claude が判断して提案した。
- 実装の細部：並び順の選択肢を1つの一覧（`SORT_ORDERS`）にまとめたこと、絞り込みは `boolean` のままにしたこと、絞り込みの判定を `src/todo.ts` に移さず App に置いたこと（レビューで指摘されたが、1行なので残した）。
- `/code-review` で基準点の指定がなかったので、未コミットの変更（`git diff HEAD`）をレビュー対象にした。
- コミットは、これまでのやり方に合わせて `main` に直接行い、メッセージに `Closes #2`・`Closes #3` を入れた。
