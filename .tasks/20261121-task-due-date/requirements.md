# 要件の質問と回答

`/grill-with-docs`（grilling スキルと domain-modeling スキル）で、決めることを「設計ツリー」として扱い、前提が決まったものから順にラウンドごとに質問した。各質問には Claude の推奨案を付け、ユーザーが Yes か別案で答えた。決まった用語は、その場で [GLOSSARY.md](../../GLOSSARY.md) に書いた。

質問の前に [docs/spec.md](../../docs/spec.md) と `src/todoData.ts` を読み、次のことを確認した。

- タスクの項目は `id`・`title`・`completed`・`createdAt` の4つで、データはバージョン1
- 仕様書では、期限は「その後の候補」で、データの形を変えるときは `version` を上げて変換処理を書くことになっている
- `GLOSSARY.md` と `docs/adr/` はまだない

## ADR について

どの決定も、あとから変えるのにそれほど手間がかからず、理由も仕様書で説明できるので、ADR は作らなかった。

## 実装のときに Claude が決めた点

会話の中では決めていなかったので、[docs/spec.md](../../docs/spec.md) やコードに明記した。

- 期限切れの赤は `rgb(198, 40, 40)`。タイトルの文字だけに付け、「期限切れ」という文字は足していない
- 日付入力欄の読み上げ名は「新しいタスクの期限日」と「「〇〇」の期限日」
- 「今日」はローカル時刻（日本時間）の日付
- 時刻付きの値（`2026-11-25T00:00:00Z` など）も、正しくない期限日としてエラーにする
- バージョン1のファイルの中身が壊れている場合も、これまでどおりエラーにする
