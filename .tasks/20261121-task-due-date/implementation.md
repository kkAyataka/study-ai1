## 3. データを TDD で作る

- 先に `src/backup.test.ts` と `src/storage.test.ts` を書き換えた。
  - 書き出したものをそのまま読み戻せる（`dueDate` 付き）
  - 書き出すデータはバージョン2
  - バージョン1は `dueDate: null` として読める（バックアップと localStorage の両方）
  - バージョン3はエラー
  - `dueDate` の欠け、存在しない日付（`2026-13-45`、`2026-02-30`）、時刻付き、数値はエラー
- 3本が失敗することを確かめてから実装した。ほかのエラーのテストは、今の実装ではバージョン2そのものがエラーになるので、最初から通っていた。
- `src/todo.ts` の `Todo` に `dueDate: string | null` を足した。
- `src/todoData.ts` では次の3つを変えた。
  - `DATA_VERSION` を2にした。
  - バージョン1は `isTodoV1` で確かめてから `dueDate: null` を足して返すようにした。
  - バージョン2は `isTodo` で `dueDate` が `null` か実在する `YYYY-MM-DD` かを確かめるようにした。実在するかどうかは、`Date.UTC` で日付を作り、年・月・日が入力と同じに戻るかで判定した。

## 4. 画面を TDD で作る

- 先に `src/App.test.tsx` に5本足した。
  - 追加するときに期限日を指定でき、追加後は日付欄も空に戻る
  - 指定しなければ期限日なしで追加される
  - 一覧で変更・解除でき、開き直しても残る
  - 期限切れの赤字（昨日が期限で未完了なら赤字。今日が期限、完了済み、期限日なしは赤字にならない）
  - 今日より前の日付も指定できる
- 日付入力欄への入力は `fireEvent.change` で行った。今日の日付は `vi.useFakeTimers({ toFake: ['Date'] })` と `vi.setSystemTime` で 2026-11-21 に固定した。`src/test/setup.ts` の `afterEach` に `vi.useRealTimers()` を足した。
- 赤字の確認は、取り消し線の既存テストに合わせて、インラインスタイルの `color` を見るようにした。
- 新しいテスト5本に加え、既存の「開き直しても残る」も失敗した。期限日のないタスクを保存すると、読み直したときにバージョン2の検査で弾かれるため。実装後はすべて通った。
- `src/todo.ts` に `toDateString`（ローカル時刻の `YYYY-MM-DD`）と `isOverdue`（未完了で、期限日が今日より前）を足した。
- `src/App.tsx` では次の2つを変えた。
  - 追加フォームと一覧の各行に `<input type="date">` を置いた。
  - 描画のたびに今日の日付を求め、期限切れならタイトルを赤字にするようにした。
- `src/backup.ts` の `backupFileName` も `toDateString` を使うようにして、同じ日付の書式の処理を1つにまとめた。
- `src/index.css` では、追加フォームの入力欄に `flex: 1` が付いていて日付欄まで広がるので、日付欄だけ `flex: 0 0 auto` にした。

## つまずいた点

- **lint の警告**: oxlint が、描画中に `new Date()` を呼ぶことを `react(purity)` で警告した。Q13 で「描き直すたびに今日と比べる」と決めたとおりの動きなので、理由を書いたコメントと `oxlint-disable-next-line react/purity` で警告を止めた。
- **関係ない変更が作業ツリーにあった**: `git status` に、このセッションで触っていない `.gitignore`・`package.json`・`package-lock.json` の変更（coverage の設定）があった。コミットには含めない予定だと伝えた。コミットするときには、これらの変更は作業ツリーから消えていて、Git の管理外の `coverage/` フォルダだけが残っていた。このセッションでは元に戻していない。
