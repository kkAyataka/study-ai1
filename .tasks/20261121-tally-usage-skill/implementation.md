# 作業の記録

## 1. 費用の計算を説明する

- claude-api スキルで Opus 5.5 の単価を確認し、統計表示の数字をトークンの種類ごとに計算した。
- 計算した合計（約 $4.15）と表示（$5.95）が合わなかった。fast mode やほかの単価の組み合わせも試したが、ぴったり合う組み合わせは見つからなかった。原因の候補（内訳にない利用、Claude Code 内部の単価表、fast mode）を挙げて、正確な額は Console で確認するよう伝えた。

## 2. プランの上限を調べる

- WebFetch が直接使えなかったので、web-fetch サブエージェントに公式ページを読ませた。
- Pro 使用量のサポート記事（8324991）は 404 だった。読めたページには具体的な回数やトークン数がなかった。
- Team の記事と料金ページから、Standard 席は Pro の 1.25倍、Premium 席は 6.25倍（5時間ごと）と分かった。週の上限の倍率は書かれていなかった。週の上限のリセットは「アカウントごとに決まった時刻」（Team の記事）と「rolling」（コストのドキュメント）で書き方が違っていた。

## 3. ログから集計する

- `~/.claude/projects/<プロジェクト>/*.jsonl` の `type: "assistant"` の行に、`message.usage`（入力、出力、キャッシュ読み取り、キャッシュ書き込みの 5分／1時間）が残っていることを確認した。
- 1つの応答が複数行に記録されることがあるので、`message.id` と `requestId` の組で重複を除いた。モデル名が `<synthetic>` の行は除いた。
- サブエージェントのログ（`isSidechain`）も同じ `sessionId` を持つので、親のセッションに含まれる。
- 今月の合計は 202 回、約 2,250 万トークンで、約 97% がキャッシュ読み取りだった。ログは 11月21日の分しかなかった。

## 4. セッションごと・依頼ごとに広げる

- セッションのタイトルは `type: "custom-title"` の行の最後の値を使った。
- 依頼ごとの集計では、ユーザーのメッセージ（ツールの結果や `isMeta` を除く）の時刻で区切り、各 API 呼び出しを直前のメッセージに割り当てた。
- 一時フォルダに `sessions-2026-11.csv` と `requests-2026-11.csv` を出した。依頼ごとに見ると、会話が長くなった後半の依頼ほどキャッシュ読み取りが増えていた。

## 5. スキルにする

- `writing-for-agents` スキル（と `SKILL-MECHANICS.md`）を読み、`record-task` と同じ手動呼び出しにした。
- `.claude/skills/tally-usage/scripts/tally_sessions.py` を作った。
  - 引数は CSV のパスだけ。`session_id` で突き合わせ、あれば上書き、なければ開始日時の順に追記する。ログのないセッションの行は残す。
  - 列の並びが違う CSV にはエラーで止まり、ファイルを変えない。
  - 書き込みは一時ファイルに書いてから置き換える。
  - `requests` はユーザーのメッセージ数、`project` はログの `cwd` のフォルダ名。
- `SKILL.md` の手順は「CSV のパスを毎回聞く → スクリプトを実行 → 追記・上書きした行を報告」。

## 確認したこと

一時フォルダのテスト用 CSV で次の5つを試し、どれも想定どおりだった。

- 新しいファイルを作る（8セッションを追記）
- 同じ内容で再実行する（追記 0、上書き 0）
- 値が古くなった行を上書きする
- ログのない行（テスト用に足した `old-session`）を残す
- 列が違う CSV でエラーになり、ファイルが変わらない

## 確認していないこと・残っている課題

- `/tally-usage` を実際に呼び出して、パスを聞くところから通しで使ってはいない。
- 統計表示の $5.95 と公開単価での計算が合わない理由は分かっていない。
- 集計に含まれないもの：claude.ai のチャット、ほかの PC やクラウドのセッション、ログが削除されたセッション（CSV に一度書いた行は残る）。
- 依頼ごとの集計（`tally_tasks.py`）はスキルに入れず、一時フォルダに置いたまま。
