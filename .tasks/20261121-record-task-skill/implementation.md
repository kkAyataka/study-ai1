# 作業の記録

## 1. スキルの書き方を確認

- プロジェクトの `writing-for-agents` スキル（と `SKILL-MECHANICS.md`）を読み、手動呼び出しにするか自動呼び出しにするかの判断基準を確認した。
- 既存スキルの構成を確認した。`.claude/skills/` の中身は `.agents/skills/` へのシンボリックリンクで、`skills-lock.json` で管理されていた。

## 2. 最初の版（Python スクリプトあり）

- `.claude/skills/record-task/SKILL.md` を作成した。手順は「範囲を決める → 既存の記録を手本にする → 使用量を集める → 4ファイルを書く → 報告」。
- `scripts/session_usage.py` を作成した。`~/.claude/projects/<プロジェクト>/` の最新のセッションログから、API 呼び出しごとの `usage` をメッセージIDの重複を除いて合計し、モデル別の料金表で API 換算コストを Markdown で出力する。`--since` / `--until` で期間を絞れる。
- 料金は claude-api スキルの料金表（Opus 5.5 / Sonnet 5.5 / Fable 5.2）から取った。
- 確認したこと:
  - ToDoアプリのタスクの期間に絞った集計（95回、出力 46,505）が、手で集計した値（94回、出力 46,206）とほぼ一致した。差はログの書き込みタイミングによるもの。
  - 期間内に呼び出しがないときは、エラーメッセージを出して終了する。

## 3. 作り直し（貼り付け方式）

- ユーザーから「`/usage` の結果をそのまま保存できないか。Python は保守が大変」と指摘を受けた。
- `/usage` を Claude から実行できるか調べた。
  - `/usage` はアプリ組み込みのコマンドで、Claude からは呼び出せない。
  - CLI 版の `claude -p "/usage"` を試そうとしたが、この Mac には CLI 版の `claude` が入っていなかった（`timeout` コマンドもない）。
- ユーザーの選択に従い、`scripts/` フォルダごとスクリプトを削除した。
- SKILL.md の手順を書き換えた。
  - 使用量を集める手順をなくし、記録ファイルを書いた後に「`/usage` を実行してレポートを貼り付けてください」とユーザーに頼んで待つ手順にした。
  - 貼り付けられたレポートは、記録日時の1行と一緒にコードブロックでそのまま `usage.md` に保存する。
  - タスクの開始時刻を探す手順（スクリプトの `--since` 用）は不要になったので削除した。

## 4. 試用

- `/record-task` を実行し、このタスク自体の記録を作った。スキルの一覧には新しいセッションを待たずに表示された。
- タスクの開始時刻（16:11 JST）は、セッションログのタイムスタンプで確認した。

## 確認していないこと・残っている課題

- デスクトップアプリの `/usage` にはセッション単位のトークン数とコストも表示されるので、貼り付け方式でもそれらは残る。ただし数字はセッション全体の合計で、記録するタスクの分だけではない（この記録の `usage.md` も、ToDoアプリ MVP の作業を含んだ値）。
- ToDoアプリの記録（`.tasks/20261121-todo-app-mvp/usage.md`）は、スクリプトで集計した形式のまま。新しい形式には合わせていない。
- スキルとこの記録はまだコミットしていない。
