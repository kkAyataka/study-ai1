# 実装と公開の記録

## 1. 土台作り

- `npm create vite@latest`（react-ts テンプレート）を作業用フォルダで生成し、必要なファイルだけプロジェクトにコピーした。既存の `.claude` / `.agents` があるフォルダに直接生成しないため。
- デモ用の画像や CSS を削除し、`index.html` の言語を `ja`、タイトルを `ToDo` にした。
- Vitest、jsdom、Testing Library を追加した。テストのたびに localStorage とモックを元に戻す設定（`src/test/setup.ts`）を入れた。
- `vite.config.ts` の `base` を `/study-ai1/` にした（GitHub Pages 用）。
- `git init -b main` で Git を始め、初回コミットを作った。

## 2. TDD での実装

tdd スキルのルールに従い、テストする場所（seam）を先にユーザーと合意してから、1テスト → 最小の実装、の順に進めた。

| テストする場所 | テスト数 | 内容 |
| --- | --- | --- |
| `storage` | 4 | 空のとき、保存して読み戻す、壊れたデータ、未対応バージョン |
| `backup` | 9 | 書き出し → 読み込み、ファイル名、JSONでない、未対応バージョン、項目の型の誤り6種類 |
| `App` | 8 | 0件の表示、追加、空白の扱い、並び順、完了の切り替え、確認付きの削除、開き直したときの保持 |

設計上のポイント:

- データ形式の変換と検証を `src/todoData.ts` にまとめ、`storage` と `backup` の両方から使うようにした。保存データと書き出しファイルの形式が同じなので、検証も1か所で済む。
- 追加・完了・削除のロジックは専用のテストを書かず、画面テストで確かめた。内部の構造を変えてもテストを書き直さずに済むようにするため。

## 3. 動作確認

- 開発サーバーを `.claude/launch.json` で起動し、アプリ内のブラウザで操作した。
- 追加・完了・再読み込み後の保持を、実際の操作で確認した。
- 書き出し・読み込みは、ページ内のスクリプトで確認ダイアログとファイル選択を代わりに動かして確認した。実際のファイル選択操作は手動で試していない。

## 4. 公開

| 手順 | 結果 |
| --- | --- |
| `gh repo create` | エラー表示が出たが、リポジトリ自体は作成されていた |
| SSH でプッシュ | 鍵の権限エラーで失敗 → HTTPS に切り替え、`gh auth setup-git` を実行（`~/.gitconfig` に設定が追加された） |
| HTTPS でプッシュ | gh のトークンに `workflow` スコープがなく拒否された |
| `gh auth refresh -s workflow` | チャット欄の `!` 実行ではブラウザ承認を待てず完了しなかった |
| 対応 | ワークフローファイルを最後のコミットから外してプッシュ。ワークフローはユーザーが GitHub 上で追加した（`deploy.yaml`） |
| Pages | ユーザーが公開元を GitHub Actions に設定 |
| ワークフロー | 「Test and deploy」が31秒で成功 |
| 公開ページ | 表示とコンソールエラーなしを確認。本番データを汚さないよう、公開URLでは操作していない |

## 残っている課題・メモ

- gh のトークンには今も `workflow` スコープがない。ワークフローを変更してプッシュするときは、先に `gh auth refresh -h github.com -s workflow` をターミナルで完了させる必要がある。
- 次のバージョンの候補：タスク名の編集、「未完了だけ表示」の絞り込み、削除の取り消し。
