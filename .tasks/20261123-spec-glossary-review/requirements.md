## ラウンド1：修正案をどこまで反映するか

Claude が13項目の修正案を3つに分けて出し、「まず文書だけで直せる A と B から手を付けるのがよい」と推奨した。ユーザーの回答は「A〜Cを反映」。

| 区分 | # | 修正案 |

## 推奨と違う回答になった点

- 推奨は A・B を先に反映することだったが、回答は C まで含めて全部反映することになった。

## Claude が独断で決めた点

C には仕様の判断が要る項目があったが、ユーザーに聞かずに次のように決め、終わってから報告した。

- **9（年0000）**：仕様（0001〜9999年）に実装を合わせた。0000年は日付入力欄に表示できず、空欄なのに赤字になる食い違いが起きるため。
- **10（読み込むファイルの検証）**：3つとも検証してエラーにすることにした。
  - `createdAt` は書き出しと同じ `toISOString()` の形式（UTC、ミリ秒付き）だけを受け付ける。時差付きの書き方も受け付けない。
  - エラーの文言は、ほかの型の誤りと同じ「タスクのデータが正しくありません。」にした。
  - このチェックは読み込むファイルにだけかけ、localStorage にはかけないことにした。弾くと空の一覧として扱われ、次の保存でタスクが全部消えるため。
- **11（テスト）**：テストを書くことにした（「手動で確認する」と書くだけにはしなかった）。
- **用語集の構成**：小見出し（タスク／一覧の見せ方／データの出し入れ）で用語を分けた。このあとユーザーが自分で小見出しを外し、その形でコミットした。
- **コミットの分け方**：コードとテストと spec.md・README.md を1つ、GLOSSARY.md を1つの、2つのコミットにした。
