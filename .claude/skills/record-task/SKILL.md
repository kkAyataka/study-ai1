この会話で最後に終えたタスクを、後から読み返せる**記録**として `.tasks/` に残す。記録は日本語で書く。

## 1. タスクの範囲を決める

会話をさかのぼり、最後のタスクの始まりを見つける。始まりは、ユーザーがそのタスクを頼んだメッセージ。そこから今までが記録の範囲。

- **日付**：タスクを始めた日（ローカル時刻）を `YYYYMMDD` にする。
- **task-name**：作ったもの・やったことを表す英語の kebab-case（例: `todo-app-mvp`）。

範囲がはっきりしないとき（1つの会話に複数のタスクがあり、どこからが「最後のタスク」か判断できないとき）は、範囲をユーザーに確認する。

## 2. 既存の記録を見る

`.tasks/` の中にある既存の記録フォルダを開き、ファイル構成と書き方をそろえる。既存の記録が手本になる。

## 3. 記録を書く

`.tasks/YYYYMMDD-task-name/` に次のファイルを作る。

| ファイル | 内容 |
| --- | --- |
| `README.md` | 日付・時間帯、モデル、成果物（URL やパス）、各ファイルへの案内、流れ、結果、コミット一覧 |
| `requirements.md` | 要件を決めたやり取り。質問・推奨案・回答をラウンドごとに表にし、推奨と違う回答になった点と、Claude が独断で決めた点を最後にまとめる |
| `implementation.md` | 作業の経緯。何をどの順にやったか、設計上のポイント、つまずいた点とその対処、確認したこと・確認していないこと、残っている課題 |

要件を決めるやり取りがなかったタスクでは `requirements.md` を作らず、README の案内からも外す。リポジトリにある仕様書などと内容が重なる部分は、写さずにリンクする。README の案内には、手順4で作る `usage.md` も入れておく。

完了の条件：範囲内のすべての決定、つまずき、コミット（`git log` で確認）が、どれかのファイルに載っている。

## 4. /usage のレポートを保存する

`/usage` は Claude からは実行できないので、ユーザーに頼む。次の内容を伝えてターンを終え、貼り付けを待つ。

> 使用量の記録のため、メッセージ欄で `/usage` を実行し、表示されたレポートをコピーしてこのチャットに貼り付けてください。

貼り付けられたら、`usage.md` を作る。冒頭に記録した日時（ローカル時刻）を1行書き、その下にレポートを**貼り付けられたとおり**コードブロックに入れる。要約、整形、数字の計算や補足はしない。

## 5. 報告する

作ったファイルの一覧を伝える。記録はコミットせずに置いておき、コミットとプッシュをするかをユーザーに聞く。
