Claude Code のログ（`~/.claude/projects/**/*.jsonl`）から、セッションごとのトークン量を集計して CSV に残す。CSV は使用量の台帳として育てていくもので、ログが自動削除された後も行が残る。ユーザーへの説明は日本語で書く。

## 1. CSV ファイルを聞く

書き込む CSV のパスを毎回ユーザーに聞き、答えを待つ。前回のパスや会話中に出たパスがあっても、それを使わずに聞く。

> 集計結果を書き込む CSV ファイルのパスを教えてください。まだないファイルなら新しく作ります。

完了の条件：ユーザーが答えたパスが1つ決まっている。そのファイルがまだない場合は、新しく作ることをユーザーに伝えてある。

## 2. 集計して書き込む

```bash
python3 -I .claude/skills/tally-usage/scripts/tally_sessions.py "<CSV のパス>"
```

スクリプトは CSV を次のように扱う。

- CSV にまだないセッションは、開始日時の順に末尾へ追記する。
- 同じ `session_id` の行がすでにあれば、最新の値で上書きする。続いているセッション（この会話も含む）は、実行するたびに数字が増える。
- ログが残っていないセッションの行は、そのまま残す。
- 列の並びが想定と違う CSV には書き込まずに止まる。そのときは、別のファイルを指定するかユーザーに聞く。

列の意味：

| 列 | 内容 |
| --- | --- |
| `start` / `end` | セッションで最初と最後に API を呼んだ日時（ローカル時刻） |
| `project` | 作業したフォルダの名前 |
| `title` | セッションのタイトル |
| `requests` | ユーザーが送ったメッセージの数 |
| `input` 〜 `cache_write_1h` | トークンの種類ごとの合計。サブエージェントの分も含む |
| `api_calls` | API を呼んだ回数 |
| `total_tokens` | トークンの合計 |

## 3. 報告する

スクリプトの出力をもとに、次の内容を伝える。

- 書き込んだファイルのパス
- 追記した行数と上書きした行数、それぞれの行の日時・タイトル・合計トークン

集計に含まれないものも一言添える：claude.ai のチャットで使った分、ほかの PC やクラウドのセッション、ログが削除された後の新しい利用。

CSV がリポジトリの中にある場合は、コミットせずに置いておき、コミットするかをユーザーに聞く。
